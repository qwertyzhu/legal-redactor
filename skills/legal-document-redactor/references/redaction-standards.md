# 脱敏规范基线对照（本地增补）

> 四套规范 → 本工具的落地参数。条款原文均已核对官方源，URL 与访问日期见文末。
> 本文件不替代律师判断；规范适用有争议时以主管机关/法院口径为准。

## 一、按去向选 profile

| 去向 | 命令 |
|---|---|
| 上传在线 AI / 可外传笔记 | `--mode ai` 或 `--profile ai`（审判人员姓名一并去掉）。验收加做「反推三问」 |
| 交法院 / 对方当事人 | `--profile production` |
| 公众号、普法、对外改写 | `--profile publish`（全体自然人「张某」，地址到县区，金额模糊） |
| 裁判文书上网 | `--profile judgment-online` |
| 只去证件、手机、邮箱、账号 | `--profile minimal` |

`publish` 不是法释〔2016〕19号的上网稿。

## 二、法释〔2016〕19号 → `judgment-online`

2016 修订，现行有效。第八至十一条于 2026-10-24 经 pkulaw 核对。

| 条款 | 工具落法 |
|---|---|
| 第八条：只隐名家事与继承当事人、刑事案件被害人及其法定代理人、证人、鉴定人、未成年人及其法定代理人 | 工具不判断案由。这几类人在 entities.json 写 `"role": "article8"`，不写 replacement |
| 第九条：保留姓氏，名以「某」替代；少数民族、外国人保留首字；同姓加阿拉伯数字 | `article8` 生成「张某」；同姓不同人「张某1」「张某2」。`publish` 对全体自然人用同一写法，那是对外改写 |
| 第十条：删除家庭住址、通讯方式、身份证号、银行账号、健康状况、车牌号、权属证书编号等；影响理解时用「×」 | 证件、手机、邮箱、账号、车牌、不动产权证号随 production 删除。带标签地址收到县/区，门牌去掉。健康状况手写 entities。家庭住址要整段删除时，把全文写入 entities，replacement 用「×」 |
| 第十一条：普通民事案件保留当事人姓名、出生日期、性别、住所地到县区；法人保留名称、住所地、组织机构代码和法定代表人；律师保留姓名、执业证号、律所 | 这些默认保留。统一社会信用代码按组织机构代码留下。审判人员姓名保留 |

## 三、工具盲区（结构性扫描 PASS 也盖不住）

以下各项（0.13.0 实测）`--auto-confident` 仍可能接不住，给 AI 前必须人工补 entities 或人工确认。`ai` 模式的 `verify --strict` 会把输出里残留的「有锚点」人名/单位/地址列为 WARN，但下列无锚点的照样看不见：

- **无锚点的姓名**：前面没有角色词（原告/被告/法定代表人…）或关系词（证人/表弟/丈夫/员工/股东…）的人名，如「小明」「张总」；装 `[ner]` 可进 suspects
- **APP / 网站 / 产品名、店铺名、账号昵称**：如「云帆视频」APP，常可反推当事人
- **无标签的护照号、微信号、QQ**（需带「护照号/微信号/QQ」等前缀才会命中；IP 地址无需标签）
- **准标识符组合**（GB/T 37964-2019：生日+性别+区县组合可反推个人）。ai 模式下建议把出生日期整段写入 entities（category=other）
- 民族、职务、健康状况、行踪轨迹等 PIPL 敏感个人信息（第二十八条口径）
- **扫描件没读出来的页**：没有文字层的 PDF 不能直接 `redact`。`ocr` 标成 uncovered 的页等于没处理。`verify` PASS 只覆盖已识别文字，原 PDF 不能交给模型。`redact-scan` 只涂证件号和电话
- **以「协议」「合同」结尾的作品名**：会和文书名称一起留下来，需手写 entities

已不再是盲区：`…日出生` / 出生日期标签、车牌号、不动产权证号（0.10.9）；「原告张测三，男」无冒号写法、「证人王某某出庭」类叙述人名、判决书正文「原告X公司（以下简称X）与被告Y公司」、无冒号或表格分栏的账号（0.13.0）；带空格的纳税人识别号、角色词与姓名之间的逗号（0.14.1）；书名号内以「协议」或「合同」结尾的文书名称不再换成某作品（0.14.2）。

## 四、验收：反推三问（上海律协 AI 指引 2.3.4）

残留扫描 PASS 之后、交付之前，逐条自问：

1. 是否仍残留可直接识别的信息？
2. **是否能通过上下文组合反推**（生日+性别+区县、作品名+案由、职务+公司规模）？
3. 是否脱敏过度、事实缺失到 AI/读者无法完成分析？

第 2 问过不去 → 把准标识符补进 entities 重跑；第 3 问过不去 → 改用模糊法替身（区间/量级）而不是删除。

## 五、为什么 ledger 不能上传（PIPL 第七十三条）

- **去标识化**：不借助额外信息无法识别特定自然人——本工具 ai 模式属此类，**ledger 就是那个「额外信息」**，故禁止外传；
- **匿名化**：无法识别且不能复原——本工具产物不构成匿名化，不要对外宣称「已匿名」。
